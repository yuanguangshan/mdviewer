# v4.19 修「页面 4.18 / 脚本 4.16，刷新没用」

## 症状

更新部署后页面顶部提示新旧混合缓存：页面是新版、`app.js` 还是旧版，用户反复刷新无效。

## 三个原因叠加

1. **`app.js` 没有版本指纹**：`index.html` 里只有 `styles.css?v=` 带指纹，`app.js`、`lib/*.js`、`vendor/*.js` 都是裸路径。
   部署后浏览器 HTTP 缓存（GitHub Pages `max-age=600`）和 CDN 边缘缓存继续给旧脚本，页面新脚本旧的组合就这么来的。
2. **Service Worker 外壳请求走 `fetch(req)`**：默认 cache 模式仍可能命中 HTTP 缓存，等于"网络优先"只优先到 HTTP 缓存那一层。
3. **提示只让用户"按 Ctrl+Shift+R"**：手机 PWA 上没有这个键，用户无解。

## 改法

**① 全部本地脚本加 `?v=` 指纹**，由 `scripts/sync-version.mjs` 单点写入：

```html
<script defer src="./app.js?v=4.19"></script>
<script defer src="./lib/md-core.js?v=4.19"></script>
<script defer src="./vendor/marked.min.js?v=4.19"></script>
```

`scripts/check-version.mjs` 新增校验：**任何本地 `<script src>` 缺指纹或版本不符即报错**。

**② SW 外壳请求改成 `fetch(new Request(url, { cache: 'reload' }))`**，明确绕过 HTTP 缓存与 CDN 边缘缓存；
离线回退增加"按路径名命中"（预缓存 key 不带 `?v=`，否则离线会 miss）。

**③ 自动修复 `hardResetApp()`**：检测到版本不一致 → 注销 SW → 删掉所有 Cache → 带 `_r=<时间戳>` 重载。
每次会话只自动做一次（防止服务端真出现新旧并存时无限重载）。

**④ 菜单加「🔄 强制更新（清缓存）」**：手动触发，随时可用，不受一次性标记限制。

## 测试

- 本地验证脚本指纹全部为 `?v=4.19`，页面/脚本版本一致
- 点「强制更新」→ URL 追加 `_r=` 并成功重载
- 128 项测试全绿

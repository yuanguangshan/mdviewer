# v4.13 编辑区源码高亮：只上色，不改字形

## 问题

编辑模式下有整块文字变紫变斜（用户截图：front matter 的 `sync_time … content_hash` 一段）。根因不是配色，是**用错了高亮器**：

编辑区的覆盖层原来用 `hljs.highlight(src, {language:'markdown'})`。hljs 的 markdown 语法是给**渲染后的 markdown** 写的，拿它高亮**源码**会出三类错：

1. **下划线跨行配对**：`sync_time:` 与 `content_` 的两个 `_` 被配成一对 `<em>`，中间十几行全部落进强调 span → 整块变紫变斜。
2. **改字形导致错位**：`.hljs-section{font-weight:700}`、`.hljs-emphasis{font-style:italic}` 会改变字宽，而覆盖层是叠在 textarea 上的"影子文字"——字宽一变，整行就和真实光标位置对不上。
3. **围栏内被当正文**：代码块里的 `# 注释` 被解析成标题。

## 改法

内核新增 `highlightMarkdownSource(src)`（`lib/md-core.js`），按行扫描源码，只输出颜色：

- front matter（首行 `---`，40 行内闭合）按 YAML 上色：键 / 字符串 / 数字 / 布尔 / 注释
- 块级：标题、分隔线、引用、列表符号、表格行、围栏（围栏内整块统一暗色，不再二次解析）
- 行内：行内代码、加粗、斜体、链接 URL；`3*4*5` 这类算式不误判为斜体

CSS 加了一道铁律：

```css
.editor-highlight, .editor-highlight * {
  font-style: normal !important;
  font-weight: inherit !important;
  letter-spacing: inherit !important;
}
```

## 不变量（测试保证）

- **去掉所有标签后必须与原文逐字相同**（`tests/editor-source-highlight.test.js`，8 项）
- 输出里不允许出现任何 `font-*` 样式
- front matter 里出现 `src-em` 即视为失败（说明 `_` 又被配对了）

共 113 项测试全绿。

## 二、v4.8：把坑填平，把测试补上

### 2.1 做了什么

纯逻辑从 5644 行的 `app.js` 下沉到 `lib/md-core.js`（730 行，零 DOM 依赖，浏览器挂 `window.MdCore`、Node 直接 `require`），因此第一次具备了"不靠手测"的可能。

| 维度 | 改前 | 改后 |
|---|---|---|
| 撤销 | 程序化改写后 `Ctrl+Z` 失效 | 自建栈（60 步 / 8MB），覆盖替换 / AI 应用 / 排版 / 插图 / 恢复历史 |
| 正则 | 用户正则跑主线程 | Worker + 3s 硬超时 + `terminate()` |
| AI | 无超时，端点挂起则永久转圈 | 60s 空闲 + 5min 总量，超时保留已生成内容 |
| 存储 | 一次写入牵动"正文 + 20 条历史"数 MB | `docs` / `history` / `positions` / `drafts` 四仓库分层 |
| 历史快照 | 每 800ms 一条全文，20 条封顶 | "5 分钟或 5% 变化"才留档 |
| 备份 | 无（清站点数据全丢） | 零依赖自研 ZIP，全库导出/恢复 |
| 可访问性 | 12 个弹窗各写各的 Esc | MutationObserver 统一接管：焦点陷阱 + `inert` + 焦点归还 |

### 2.2 三个清单之外的真 bug

1. **同步护栏拦不住 ReDoS**。第一版给正则加了"循环里查时间预算"，然后写了个灾难性回溯的测试 —— 测试直接挂死 30 秒。根因：回溯发生在**单次 `exec()` 内部**，JS 无法中途打断，"循环查预算"只能拦住"匹配次数爆炸"。改用 Worker + `terminate()` 才是正解，且 Worker 内的逻辑本体仍是纯函数、仍被单测覆盖。
2. **`libimg://` 真的会发起网络请求**。DOMPurify 消毒前会先把字符串解析成 DOM，`<img src="libimg://...">` 一进 DOM 浏览器就去请求，控制台持续刷 `ERR_UNKNOWN_URL_SCHEME`。修法：在 sanitize **之前**用字符串预替换成 1×1 占位图 + `data-libimg`。
3. **导出丢图**。改快照时用 `preview.innerHTML`（里面是 `blob:` 临时 URL），而 `inlineLibImages` 只认 `libimg://`。补充 `snapshotPreviewHtml()` 做字符串反查 —— 注意**不能**用 `cloneNode` 再改 `src`：游离节点设 `src` 一样会触发请求（第 2 个坑的变体）。

### 2.3 验收

```
npm test                → 37/37
tests/e2e_smoke.py      → 38/38（真 Chromium：渲染/去重/撤销/ReDoS/文库/快照策略/zip/焦点陷阱/方向键）
15 files, +2804 −384  → 提交 2d22bec → 推送 → Pages 生效 v4.8
```

## 三、R2 桶：一次真实的"开放端点被当靶场"

### 3.1 取证过程

用户怀疑被攻击，给了桶对象列表。我把 <30KB 的 22 个对象全部拉下来分类（**只读，不执行**）：

| 类别 | 样本 | 数量 |
|---|---|---|
| 正常文档 | `0d998f67`(22.75KB)、`112fe442`、`158d021b`… | 6 |
| 探测串 | `need_fuck=yes`(13B)、`1=1`(3B)、`{"requests":[]}`(15B) | 10 |
| 覆盖测试 | `# 自动验证 v2 / 这是覆盖后的第二版内容（overwritten）` | 1 |
| **攻击载荷** | `515497d3` / `5721bca3` / `6db9529c`（7.4KB ×3） | 3 |
| 遗留 | `5646f0f9` 含 14 张外链成人图 | 1 |

### 3.2 载荷拆解（三层嵌套）

```
multipart/form-data  →  gzip(1f8b0800)  →  Next.js RSC 外壳  →  base64  →  Node.js 脚本
   WebKitFormBoundary     7.4KB              status:"resolved_model"    9581 字符
                                             _prefix / $B0 / $THf5ezaL_5
```

解出来自称 `fast_recon_v6 — signature-rotated recon payload`，行为清单：

- `import('fs')` / `import('os')` / `readFile`
- `process.env`、`~/.aws`、`id_rsa`、`/proc/*`
- **请求 `169.254.169.254`（云元数据服务 IMDS）窃取临时凭据**
- 反检测：随机化顶层 JSON key、打乱文件读取顺序（躲 EDR）、IMDS 请求随机 UA + 抖动超时

### 3.3 结论：投递成功，执行失败

| 判断项 | 结果 |
|---|---|
| 载荷被执行了吗 | ❌ 对象存储只存不执行，Worker 只是 `put` 字节 |
| 打到 mdviewer 了吗 | ❌ 这是打 **Node 服务端**的；本站是纯静态 PWA + Worker，没有 Next.js |
| 打开这些"文档"会执行吗 | ❌ 走 `marked → DOMPurify`，且内容是 base64 文本 |
| 数据泄漏了吗 | ❌ 无任何迹象 |

**真正的问题不是被黑，而是：任何人 POST 一下就能往你的桶里写东西，也就能覆盖你的协作文档。**

## 四、v4.9：第 1 层加固（三步灰度）

### 4.1 拦截规则

| 规则 | 状态码 | 挡掉的真实样本 |
|---|---|---|
| `Content-Type` 必须 `text/markdown` | 415 | multipart / form-urlencoded / JSON 探测 |
| 拒绝 `Content-Encoding` | 415 | **全部 3 份 gzip 攻击载荷**（浏览器无法设置该头，零误伤） |
| 正文 ≤ 2MB（头部 + 真实字节双重校验） | 413 | 大体积灌注（沿用现网既有上限，不引入行为回退） |
| `id` 必须 `8位小写hex.md` | 400 | 路径穿越 / 桶内乱写 |
| `X-Mdviewer: 1`（灰度开关） | 403 | 无脑扫描器 |

### 4.2 为什么必须三步走（这次最重要的工程判断）

实测线上旧 Worker 的预检只放行 `Content-Type`：

```
access-control-allow-headers: Content-Type      ← 没有 X-Mdviewer
```

于是**两头都堵**：

- 前端先发（带自定义头）→ 浏览器预检失败 → "生成分享链接"直接报错；
- Worker 先上且强制校验头 → 还没刷新的老页面写入 403。

所以：**第 1 步部署 Worker 但不开开关**（过滤立即生效、老前端仍能写）→ **第 2 步发前端**（带 `X-Mdviewer`，此时预检已放行，零中断）→ **第 3 步打开 `REQUIRE_CLIENT_HEADER=1`**。

### 4.3 上线与验证

| 步骤 | 结果 |
|---|---|
| Worker 灰度 | Version `e7b0db20`；A–I 九项验证全绿（含"既有文档 md5 一致""健康检查保留""路径穿越 400"） |
| 前端 v4.9 | `e46fffc` → Pages 生效；真浏览器点"生成分享链接"→ 拿到链接 → 打开回读成功，控制台零报错 |
| 打开开关 | Version `704aaaa4`；不带头 403、带头 200、gzip 仍 415、读路径不受影响 |
| 清理 | 删 17 个（含 3 份载荷 + 我的探测对象）；抽查被删全 404、自有 10 篇全 200 |
| 桶现状 | 85 个对象 / 8.08 MB |

### 4.4 一个诚实记录

验证时我一度以为"读路径坏了"——其实是脚本只等了 2.5 秒，冷启动的浏览器上下文还没加载完。**是测得太急，不是功能问题**，延长等待后 1 秒内正常。写进日志是为了提醒自己：验证脚本的等待时间也是要设计的。

## 五、workspace 常驻服务（launchd + SSH 隧道 + 看门狗）

需求：把沙箱里的工作目录用浏览器打开，且要"系统服务 + watchdog"。

### 5.1 架构

```
Mac (10.0.0.4)                                   沙箱 (10.0.0.10)
launchd: com.yuangs.workspace-serve
  KeepAlive=true, ThrottleInterval=10
     └─ /usr/bin/ssh ──── WireGuard ────▶ exec /bin/sh /root/serve-web-launch.sh
          -L 127.0.0.1:8093 → 127.0.0.1:8080        └─ exec node /root/serve-web.js :8080
   浏览器 → localhost:8093
```

关键设计：**远程命令就是服务本体**。node 一死 → SSH 会话结束 → launchd 重建整条链路（重连 + 重启远程服务），两端都自愈，只需一个 launchd 任务。

### 5.2 踩过的三个坑

1. **端口撞车**：Mac 的 `8080` 被 `podcastd` 占、`8090` 被 `knowly-daemon` 占 → 本地改用 `8093`，并加 `ExitOnForwardFailure=yes`，撞车立即失败而不是静默假连。
2. **`pkill -f` 自杀**（最坑）：远程命令同时写了 `pkill -f "[s]erve-web\.js"` 和 `exec node /root/serve-web.js`，方括号只防住了前半段，后半段的 `.js` 让 pkill 匹配到自己的 shell → 会话被杀 → **ssh 只返回 255，不打印任何原因**，白查两轮。修法：把启停逻辑挪进 `/root/serve-web-launch.sh`（脚本 cmdline 不含 `.js`）。
3. **容器重建会换主机密钥**：用 `StrictHostKeyChecking=no` + `UserKnownHostsFile=/dev/null`（流量本就在 WireGuard 内），否则看门狗会永久卡在握手失败。

### 5.3 静态服务本身

不用 `python3 -m http.server`（它会把 `.ssh`、`.pi` 一并吐出来）。自写 `serve-web.js`（零依赖 ~180 行）：

- **白名单挂载**：`/mdviewer` → `/root/mdviewer`、`/workspace` → `/workspace`，其余 404
- `realpath` 后再校验前缀（符号链接也逃不出去）；默认隐藏点号文件；只读（GET/HEAD）
- Range / ETag / 304；可选 Basic 认证（`SERVE_PASS`）

安全自测：`/etc/passwd`、`/mdviewer/.git/config`、`/../root/.ssh/id_ed25519`、URL 编码变体 → 全部 404。

### 5.4 看门狗实测

| 故障注入 | 结果 |
|---|---|
| `pkill` 沙箱里的 node | 立即 000 → **5 秒自动恢复**（pid 变更） |
| `kill -9` Mac 上的 ssh | 立即 000 → **3 秒自动恢复**（pid 变更） |

脚本已备份到 Mac：`~/Library/Application Support/workspace-serve/`，容器重建后一条 `scp` + `kickstart` 即可恢复。

## 八、可复用的经验（下次直接抄）

1. **无法在 `exec()` 中途打断正则**。凡是"用户输入 + 正则"跑在 UI 线程，就必须 Worker + 超时；循环里查预算只解决"次数爆炸"。
2. **灰度开关是跨端改动的必需品**。只要"前端加头"和"后端校验头"同时存在，就一定会有一段全坏窗口；把校验做成变量，就有零窗口的三步路径。
3. **`pkill -f` 会匹配自己**。任何"命令行里同时包含 kill 模式和目标串"的写法都要么用方括号技巧、要么把逻辑挪进脚本。
4. **游离 DOM 也会发请求**。`cloneNode` 出来的 `<img>` 设 `src` 一样触发网络；要改属性做快照就用字符串处理。
5. **对象存储不会执行任何东西**。收到攻击载荷 ≠ 被入侵；判断标准是"有没有执行路径"，而不是"桶里有没有脏文件"。
6. **公网可写端点的默认假设应该是"一定会被扫"**。上线第一天就该有：类型白名单、体积上限、内容编码拒绝、速率限制、被拦日志。
7. **验证脚本的等待时间也是设计的一部分**。给冷启动留够时间，否则会得出"功能坏了"的错误结论，浪费一整轮排查。

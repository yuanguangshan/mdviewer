# 分享接口（share.want.biz）第 1 层加固 · 上线 Runbook

> 日期：2026-11-01 ｜ 版本：mdviewer v4.9 ｜ 范围：只做「写入闸门」，不做鉴权（第 2 层另议）

---

## 一、为什么改

R2 桶（`share`）里自 2026-07 起陆续出现非本应用写入的对象：

| 样本 | 大小 | 性质 |
|---|---|---|
| `need_fuck=yes` ×7 | 13 B | 手工/扫描器测试串 |
| `1=1` | 3 B | SQL 注入探测 |
| `{"requests":[]}` ×2 | 15/16 B | JSON 接口探测 |
| `515497d3.md` `5721bca3.md` `6db9529c.md` | 7.4 KB（gzip，解压 14 KB） | **真攻击载荷**：multipart + gzip + Next.js RSC 漏洞外壳，内含 `fast_recon_v6` —— 读取 `process.env` / `~/.aws` / `id_rsa` / `/proc/*`，并请求云元数据服务（IMDS）窃取凭据，专为规避 EDR 做了随机化 |

**没有被攻破**：对象存储只存不执行，载荷全部「投递成功、执行失败」。问题是**写入口对全世界开放**。

---

## 二、改了什么

| 文件 | 作用 |
|---|---|
| `lib/share-guard.mjs` | 策略本体（纯函数，ESM）：类型/编码/体积/id 校验。**有单测** |
| `worker/share-worker.mjs` | 完整可替换的 Worker 实现，接入上面的策略 + 灰度开关 |
| `tests/share-guard.test.js` | 10 条策略单测 |
| `tests/share-worker.test.js` | 14 条 Worker 集成测试（假 R2 桶，真跑 handler） |
| `scripts/check-worker.mjs` | 本地校验 Worker 能作为 ESM 加载（CI 无 `worker/` 时自动跳过） |
| `app.js` | `shareViaR2()` 多带一个请求头 `X-Mdviewer: 1` |

拦截规则（任何一条命中即拒，且**不带任何前端改动也生效**）：

| 规则 | 状态码 | 挡掉的是 |
|---|---|---|
| `Content-Type` 必须是 `text/markdown` | 415 | multipart / form-urlencoded / JSON 探测 |
| 拒绝 `Content-Encoding` | 415 | **全部 3 份 gzip 攻击载荷** |
| 正文 ≤ 2MB（沿用现网既有上限；头部 + 实际字节双重校验） | 413 | 大体积灌注 |
| `id` 必须是 `8位小写十六进制.md` | 400 | 路径穿越 / 桶内乱写 |
| `X-Mdviewer: 1`（灰度开关，第 3 步才打开） | 403 | 无脑扫描器 |

外加：所有被拦请求打一行日志（`wrangler tail` 可见 IP/UA/大小），便于观察波次。

## 三、三步上线（顺序不能错）

> **为什么必须分三步**：实测线上旧 Worker 的预检只允许 `Content-Type`，所以「前端先发」会因 CORS 预检失败而**立刻坏掉分享**；而新 Worker 若一上来就强制请求头，会让还没刷新的老页面 403。两头都堵，才需要灰度开关。

### 第 1 步｜先部署 Worker（`REQUIRE_CLIENT_HEADER` 不设）

```bash
cd <你的 worker 目录>          # 例如 ~/mdviewer/worker
# 用本仓库的 lib/share-guard.mjs + worker/share-worker.mjs 覆盖你的实现
# 确认 wrangler.toml 的 main 指向 share-worker.mjs，且保留 R2 绑定：
#   [[r2_buckets]]
#   binding = "R2_BUCKET"
#   bucket_name = "share"
npx wrangler deploy

# 验证 A：预检现在允许 X-Mdviewer（这一步不通过，说明 CORS 没更新）
curl -s -D - -o /dev/null -X OPTIONS https://share.want.biz/ \
  -H "Origin: https://md.want.biz" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type,x-mdviewer" \
  | grep -i access-control-allow-headers
# 期望：access-control-allow-headers: Content-Type, X-Mdviewer

# 验证 B：gzip 载荷被拒（用 PUT 打到已有的垃圾 id，避免再产生新对象）
printf '\x1f\x8b\x08\x00' > /tmp/gz.bin
curl -s -o /dev/null -w "%{http_code}\n" -X PUT https://share.want.biz/3586819e.md \
  -H "Content-Type: text/markdown" -H "Content-Encoding: gzip" \
  --data-binary @/tmp/gz.bin
# 期望：415

# 验证 C：multipart 被拒
curl -s -o /dev/null -w "%{http_code}\n" -X POST https://share.want.biz/ \
  -H "Content-Type: multipart/form-data; boundary=x" --data-binary '--x--'
# 期望：415

# 验证 D：老前端（不带 X-Mdviewer）仍能分享 ← 灰度期必须为 200
curl -s -o /dev/null -w "%{http_code}\n" -X PUT https://share.want.biz/3586819e.md \
  -H "Content-Type: text/markdown" --data-binary 'gray-period-probe'
# 期望：200
```

### 第 2 步｜发布前端（v4.9）

此时前端会带 `X-Mdviewer: 1`，而 Worker 已放行该头 → 分享功能**无中断**。

```bash
# 部署后确认页脚是 v4.9
curl -s https://md.want.biz/ | grep -o 'class="version">v[0-9.]*'
```

线上手工验证一次：写几个字 → 「⋯ → 🔗 生成分享链接」→ 能拿到链接 → 打开链接能读到内容。

### 第 3 步｜打开开关

```bash
cd <你的 worker 目录>
# 方式一：wrangler.toml 里加 [vars] REQUIRE_CLIENT_HEADER = "1"
# 方式二：npx wrangler secret put REQUIRE_CLIENT_HEADER   （值填 1）
npx wrangler deploy

# 验证：不带头的写入应被 403 拒绝
curl -s -o /dev/null -w "%{http_code}\n" -X PUT https://share.want.biz/3586819e.md \
  -H "Content-Type: text/markdown" --data-binary 'should-be-blocked'
# 期望：403
```

## 四、清理存量垃圾（第 4 步，可选但建议）

R2 的 HTTP 接口不支持 DELETE（405），要用 wrangler：

```bash
cd <你的 worker 目录>
BUCKET=share
for id in 3586819e 45377634 53a47e36 58869001 6c099a0a 782fea82 7f2723b3 \
          29f61cee 0da12a7b 7c2bc32c 1c4381e9 2786cb9a \
          515497d3 5721bca3 6db9529c; do
  echo "删除 $id.md"
  npx wrangler r2 object delete "$BUCKET/$id.md" --remote
done
```

注意事项：

- **别删你自己的文档**：`0d998f67` `112fe442` `158d021b` `3900152a` `3c23dc2a` `63ba9dbd` `5646f0f9` `da21cb50` 等是正常内容。
- `2786cb9a.md` 是本次排查时我做的连通性探测（21 B），一并删掉。
- 建议顺手开 **R2 生命周期规则**（例如 90 天未更新自动过期），防止长期堆积。

## 六、监控

```bash
cd <你的 worker 目录>
npx wrangler tail --format pretty
```

被拦请求会打印：

```
[share] blocked unsupported-media-type { status: 415, method: 'POST',
  ct: 'multipart/form-data; boundary=----WebKitFormBoundary…',
  ce: null, len: '7404', ip: 'x.x.x.x', ua: '…' }
```

建议观察 3～7 天的分布：若 `blocked` 量骤增或出现新的 `reason`，说明扫描器换了手法，
再考虑第 2 层（HMAC 时间戳签名 / 用户自填令牌 / Cloudflare Access）。

## 七、第 2 层（本次不做）

第 1 层能挡扫描器与自动化滥用，**挡不住看过源码后手工构造请求的人**。要升级：

- `X-Md-Ts` + `X-Md-Sig = HMAC-SHA256(secret, ts + '.' + bodyLen)`，5 分钟有效期防重放；
- 但密钥放前端 JS 里只是「提高门槛」——真安全需要用户自填令牌（BYOK，与 AI Key / NAS 凭据一致）或 Cloudflare Access。

`worker/share-worker.mjs` 文件末尾已写好这两步的代码骨架，需要时取消注释即可。

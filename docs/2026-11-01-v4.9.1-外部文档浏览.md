# v4.9.1 外部文档浏览模式（`?open=`）：让 serve-web 里的 `.md` 用 mdviewer 排版阅读

> 日期：2026-11-01｜版本：v4.9.1｜工作量：约 48 行（mdviewer 44 行 + 版本脚本 1 行 + serve-web 3 行）

---

## 一、需求

`serve-web.js` 把容器里的 `/workspace`、`/root/mdviewer` 映射到浏览器后，`.md` 以 `text/markdown` 直出，
浏览器只能显示纯文本——表格、代码块、公式全成了原文，实测解剖报告、开发日志这类长文档读起来很难受。

目标：在目录列表里点一个 `.md`，直接以 mdviewer 的排版效果阅读，**不引入任何第三方渲染库**。

## 二、三条候选路径与取舍

| 方案 | 做法 | 结论 |
|---|---|---|
| A 服务端渲染 | serve-web 里塞 marked 做 SSR | ❌ 违背"零依赖"设计，且要另写模板 |
| B 公网 PWA 读本地 | `md.want.biz?open=http://localhost:8080/...` | ❌ **双杀**：https 页面 fetch http 资源 = mixed content；跨源还要 CORS |
| C 同源参数（采用） | `?open=<同源路径>`，mdviewer 自己 fetch | ✅ 同源 → 无 CORS、无 mixed content、零新增依赖 |

关键洞察：mdviewer **本来就由 serve-web 提供**（挂载点 `/mdviewer`），与 `/workspace` 同源同端口，
所以"打开容器里的 md"根本不需要跨源，只需要一个参数入口。

## 三、实现

### 3.1 `app.js`：`openExternalDocFromQuery()`

挂在 `initLibrary()` 最前面（在 `?share_r2=` 之前）：

```js
if (await openExternalDocFromQuery()) return;
```

要点：

1. **同源校验**：`new URL(raw, location.href)` 后比较 `origin`，跨源直接报错并 return，
   避免把编辑器变成任意 URL 抓取器（外部文档请继续走 `?share_r2=`）。
2. **状态隔离**：`currentLibId = null`、`currentShareId = null`、`currentNameIsAuto = false`
   —— 不写文库、不把外部文档当协作文档（否则点「生成协作链接」会覆盖别人的 R2 对象）。
3. **走正常渲染管线**：`editor.value = text` + `afterChange({ skipWriteback: true })` + `syncPodcastOnLoad()`，
   表格/代码块/公式/TOC 全部复用既有实现。
4. **失败可退**：HTTP 非 2xx 时提示后 `return false`，回落到文库/草稿初始化，不把用户卡在空白页。
5. 文件名取 URL 末段并 `decodeURIComponent`，中文标题正常。

### 3.2 `serve-web.js`：目录列表加「📖 阅读」

```js
const isMd = !isDir && /\.(md|markdown)$/i.test(e.name);
rows.push({ name, href, isDir, isMd, ... });
// 行内：
// 📄 <a href="${r.href}">${name}</a> · <a href="/mdviewer/index.html?open=${encodeURIComponent(r.href)}">📖 阅读</a>
```

原文件名链接保留（想看 raw / 让浏览器下载仍可点）。

### 3.3 顺手修掉 `scripts/sync-version.mjs` 的真 bug

`styles.css?v` 被写成**全版**（`4.9.1`），而 `check-version.mjs` 期望**短版**（`4.9`）——
**任何一次版本 bump 都会让 `npm run check` 失败**。v4.9 时全版==短版，所以从未暴露。

```js
- `href="./styles.css?v=${version}"`
+ `href="./styles.css?v=${short}"`   // 与 check-version 一致：资源指纹用短版
```

## 五、坑

1. **`pkill -f` 自噬（再次复现）**：`pkill -f "serve-web.js --host 127.0.0.1 --port 8099"` 把执行它的 shell 一起杀了
   （模式串与自身命令行共处一行，必然自匹配）。关临时实例请用 pid 或 `[s]erve-web` 之类不共处一行的写法。
2. **测试路径别想当然**：`?open=` 里的路径是**URL 路径**（`/mdviewer/docs/x.md`），不是容器内的文件系统路径
   （`/root/mdviewer/docs/x.md`），第一次测试就因为写错路径得到 404 而误判为"新代码没生效"。

## 六、部署与限制

| 项 | 说明 |
|---|---|
| 生效范围 | **只在 serve-web 提供的同源环境**（`localhost:8080/8093`）。`md.want.biz` 上 `?open=` 无意义，公网分享仍用 `?share_r2=` |
| 持久化 | `/root/serve-web.js` 一旦丢，Mac 端 launchd 的 `exec node /root/serve-web.js` 就会整条失败 → 权威副本三处：本仓库 `ops/serve-web.js`、沙箱持久区 `/workspace/ops/serve-web.js`、Knowly 归档 |
| 自动恢复 | `watchdog.sh` 新增 **4c** 段：运行副本缺失时从 `/workspace/ops/` 回填；内容不一致时**只告警不覆盖**（避免把热改文件冲掉） |
| SW 缓存 | `app.js`/`index.html` 为网络优先，无需担心旧壳；`CACHE_NAME` 已随 bump 变为 `md-editor-v4.9.1` |
| 只读语义 | 外部文档不落 IndexedDB；想改就用 `Ctrl/Cmd+S` 另存，不会回写源文件 |

### 6.1 容器重建后的恢复顺序

```bash
# ① watchdog 自动做（60 s 内）：/workspace/ops/serve-web.js → /root/serve-web.js
# ② Mac 端 launchd 自带重试：SSH 会话断开 → 秒级重连 → exec node /root/serve-web.js
# ③ 若 launchd 侧脚本本身也丢了（Mac 重装），本仓库的 ops/ 目录是最后的副本来源
```

Mac 侧一次性备份（把沙箱里的新版拷回 launchd 的脚本目录，可选但建议）：

```bash
scp root@10.0.0.10:/root/serve-web.js ~/Library/Application\ Support/workspace-serve/
launchctl kickstart -k gui/$(id -u)/com.yuangs.workspace-serve
```

## 八、事故记录（同日踩到）

### 8.1 `pkill -f` 自噬（第二次复现）

```bash
pkill -f "serve-web.js --host 127.0.0.1 --port 8099"   # ← 把自己一起杀了，exit 143
```

模式串与执行它的 shell 命令行共处一行 → 必然自匹配。这与 `docs/2026-11-01-开发日志-workspace服务.md` 记的「4.2 坑」是同一个；
关临时实例请用 pid，或用不共处一行的写法（`pkill -f "[s]erve-web.js"` 也只是把风险挪到别处，最稳还是 `kill <pid>`）。

### 8.2 watchdog 的 pidfile 守卫存在重启竞态

`kill` watchdog 让 supervisord 拉起新实例时，**第一次重启的实例撞上旧 PID 文件、走进「已在运行」分支后立即退出**，
造成约 **2 分钟看守空窗**（19:07 → 19:09:43），期间 sshd / wg0 / wxwatcher 无人照看。
第二次重启才稳定。根因是守卫只看「pid 是否存活 + comm 是否匹配」，没有宽限期去容忍"旧进程刚被 SIGTERM、尚未被回收"的窗口。

**建议改法（未实施）**：`OLD_COMM` 匹配后不直接 `exit 0`，而是先 `sleep 3` 再复查一次，
或让 supervisord 侧加 `startsecs=5`；彻底一点是改成 `flock` 独占锁（`backup-all.sh` 已用这个模式）。

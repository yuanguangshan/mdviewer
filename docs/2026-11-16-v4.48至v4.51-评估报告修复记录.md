## 一、P0：会丢数据或有安全影响

### 1.1 根因：9 条加载路径各自手动重置状态

**症状**（三个独立事故，同一个根因）：

| 漏掉的变量 | 后果 |
|---|---|
| `currentShareId` | 打开别人的协作链接 → 再开自己的文库文档 → 点「生成分享链接」→ **把协作者的文档整篇覆盖成你的** |
| `currentFileHandle` | 打开 NAS 文件后 Ctrl+S → **把 NAS 内容原地写进上一个本地文件** |
| undo 栈 | Ctrl+Z → **把上一篇文档的快照套到当前文档**，再保存就串了 |

**修法**：收敛成一个函数，所有加载路径必须先调它。

```js
function resetDocContext() {
  currentShareId = null;
  currentFileHandle = null;
  docTrust = 'own';
  remoteOrigin = null;
  remoteHref = '';
  editor.readOnly = false;
  document.body.classList.remove('remote-mode');
  hideRemoteBanner();
  resetUndo();
  stopPodcastPoll();
  currentSearchHit = null;
  lastRenderedSrc = null;
}
```

接入的路径：`openFile`（FSA）、`fileInput` 降级、新建、`openLibDocData`、`nasOpen`、`openExternalDocFromQuery`（`?open=`）、`openNasDocFromQuery`（`?nas=`）、`share_r2`。

**验证**：脚本复核 6 个函数全部 ✅。

### 1.2 根因：程序化改写走了 8 条不同的路，全都清空原生撤销栈

`editor.value = ...` 会让浏览器丢弃撤销历史，而这些路径又没 `pushUndo`。

| 路径 | 后果 |
|---|---|
| **Tab 缩进** | 写代码块时几乎每行都按 → 撤销历史被一路清空（影响最大） |
| `wrapSelection`（Ctrl+B 等） | 加粗后 Ctrl+Z 无效 |
| `prefixLines`（Ctrl+1..6） | 同上 |
| `insertPodcastAtCursor`、`fmtImage` 的 URL 分支 | 同上 |
| 6 处 AI `onApply` | 与 README「AI 应用可撤销」的承诺不符 |

**修法**：一个原语。

```js
function replaceRange(s, e, text, opts) {
  if (editor.readOnly) return false;
  editor.focus();
  editor.setSelectionRange(s, e);
  let ok = false;
  try { ok = document.execCommand('insertText', false, text); } catch (_) {}
  if (!ok) { pushUndo(...); editor.setRangeText(text, s, e, 'end'); }
  if (opts.select) editor.setSelectionRange(opts.select[0], opts.select[1]);
  return true;
}
```

`execCommand('insertText')` 虽然被标记废弃，但它是目前**唯一**能把改动写进原生撤销栈的方法。失败时退回快照，功能不丢。

替换了 Tab、`wrapSelection`、`prefixLines`、播客插入、`fmtImage`、6 处 AI 应用，共 11 个点。

### 1.3 安全：他人分享的文档按"自家文档"信任级别渲染

**根因**：`remoteOrigin` 一个变量同时表示两件事——"来自外网"和"只读"。
而 `?share_r2=` 是**别人写的、但你可以编辑**的，于是落进了宽松档。

后果：
- `<audio autoplay>` 一打开就出声
- 裸链接自动变 `<img>` 请求 → 暴露 IP 和阅读时间
- `<form>` / `<input>` 原样保留 → 一篇分享文档能伪造「NAS 凭据已过期，请重新输入」的表单
- 而 localStorage 里明文存着 `nas-auth`（`user:password`）、`knowly-token`、AI Key

**修法**：可编辑 ≠ 可信任。

```js
let docTrust = 'own';   // 'own' | 'untrusted'
function isUntrusted() { return docTrust === 'untrusted' || !!remoteOrigin; }
```

| 行为 | own | untrusted |
|---|---|---|
| 消毒档位 | `LOCAL_SANITIZE` | `REMOTE_SANITIZE` |
| `<audio>` / `<form>` / `<input>` | 保留 | 剔除 |
| 裸链接自动变图 | 是 | 否 |
| markdown 图片 | 直接加载 | **占位，点击才加载** |

认领机制：存入文库 / 外部文档认领 → 弹确认 → 升为 `own` 并强制重渲。

**验证**：同一段恶意内容，own 档 `audio:True form:True input:True`，untrusted 档全 `False`；线上实测 `{ audio: false, imgBlocked: true }`。

### 1.4 时光胶囊：设备 ID 每次调用都重新生成

```js
const a = new Uint8Array(4);                                    // 4 字节
d = Array.from(a).map(b => (b % 36).toString(36)).join('').slice(0, 6);  // → 4 个字符
if (!/^[0-9a-z]{6}$/.test(d)) { ... }                           // 要求 6 位 → 永远失败
```

一次保存要调 4 次 `capDevId()` → 文件名、JSON 的 `dev`、索引的 `dev`、本地缓存的 `dev` **是 4 个不同的值**。

修法：6 字节一对一映射。验证两次调用都返回 `25nbc9`。

### 1.5 时光胶囊：索引「读-改-写」并发丢更新

`capFlushPending` 在循环里对多条并发调用 `capMergeIndex`（还 `.catch()` 掉不 await）。两个合并同时跑，各自读到同一份旧索引、各自写回 → 后写的覆盖先写的。

修法：promise 链串行化。

```js
let capIdxChain = Promise.resolve();
async function capMergeIndex(newItems, auth) {
  const run = async () => { /* 读 → 合并 → 写 */ };
  capIdxChain = capIdxChain.then(run, run);
  return capIdxChain;
}
```

顺带修了墓碑裁剪：原来 `slice(-800)` 按时间淘汰，会先丢掉早期墓碑 → 删掉的条目重新出现。现在墓碑优先保留。

### 1.6 离线白屏：预缓存 key 和运行时请求对不上

页面引用 `./lib/md-core.js?v=4.48`，SW 预缓存的 key 不带查询串。`cache.match(req)` 默认要求查询串一致 → **预缓存对这些文件形同虚设**。

触发：首次访问时页面还没被 SW 控制 → 这些请求不进运行时缓存 → 断网后打开 → `md-core` / `marked` / `purify` / `highlight` 全部 miss → 白屏。

修法：`cache.match(req, { ignoreSearch: true })`。

## 二、P1：可用性与隐私

| 编号 | 问题 | 修法 |
|---|---|---|
| P1-1 | 标题含公式时 TOC 显示 `质能 xMDVMATHx0x`，锚点同步失效 | slug 前先 `restoreMathSource` 还原成 TeX |
| P1-2 | `syncPreviewToLine` 自己 slug 一遍，规则和别处不一致 | 反查 `headingLineMap`（`Map<slug, 行号>`） |
| P1-3 | 查找框里按 Ctrl+B 会改正文 | `GLOBAL_SHORTCUTS` 白名单，其余不穿透输入框 |
| P1-4 | SSE 末位 token 丢失；AI 回填位置错乱 | flush decoder + 校验选区未变 |
| P1-5 | 文库同步污染 NAS | `.md`→`.txt`（避免触发归档流水线）+ `_libSyncing` 守卫 |
| P1-6 | 播客自动请求 + 静默改正文；新建自动读剪贴板 | 播客默认关；新建改空白，另给 `mod+alt+shift+N` |
| P1-7 | 只读模式下打开文库文档继承 readOnly | `resetDocContext` 清 remote 状态；Vim 路径加保护 |

### 值得单独说的两条

**P1-2 我第一版写错了。** 以为 `buildHeadingLineMap` 返回数组（`[{line, slug}]`），实际返回 `Map<slug, 行号>`。测试时才发现的，改成 `forEach` 遍历取「行号 ≤ 当前行的最大者」。

**P1-5 换扩展名是关键。** `{id}.md` 传到 NAS 会触发「AI 提标题 + 归档」流水线，同名再传还留一份 `_时间戳` 副本——文库每改一次就多一份归档。文库正文本来就在 IndexedDB，NAS 那份只是异地备份，改成 `.txt` 后不再被当成知识库条目。

**P1-6 是隐私问题。** 原来每次打开文档都请求 `pic.want.biz/podcast.xml`——公网站点的**每个访客**都会向作者服务器报到一次；命中后还会**静默改正文并回写**，包括别人的协作文档，再分享出去就把这段内容带给了对方。

## 三、P2：小问题

| 编号 | 问题 | 修法 |
|---|---|---|
| P2-1 | `offsetTop + parseInt(x) \|\| 0` 优先级错，工具条可能跳到顶部 | `(parseInt(x,10) \|\| 0)` |
| P2-2 | `askConfirm` 无容器时默认 `true` → 危险操作自动执行 | 默认 `false` |
| P2-3 | `copyHTML`/`exportPDF` 没等公式渲染 | 补 `await mathRendering` |
| P2-4 | 备份恢复图片 MIME 丢失 | manifest 存 `imageTypes` |
| P2-5 | `insertImage` 的 alt 没转义 `]` | `mdAltText()` |
| P2-6 | `.sessions/` 未忽略 | `.gitignore` |
| P2-7 | 胶囊文案写着"加密"（实际已改明文） | 改为"明文存你自己的 NAS" |

**P2-2 是潜在的数据事故。** `askConfirm` 用在「新建会丢失未保存内容」「删除文档」「恢复备份会覆盖」这些地方。容器一旦没渲染出来，这些操作会跳过确认直接执行。兜底逻辑默认值选错的杀伤力比大多数显式 bug 大。

**P2-3 的根因是两条导出路径不一致。** `exportHTML` 早就 `await mermaidRendering` + `await mathRendering` 了（注释里甚至写着"这就是公式不保真的根因"），但 `copyHTML` 和 `exportPDF` 是后来加的，复制粘贴时漏了这两行。

| 项 | 说明 |

### 4.2 其它已知项

- `updateGutter` 每行一个 div，5 万行 = 5 万节点，未虚拟化
- `renderEditorHighlight` 3000 行以内每帧全量 `innerHTML`
- 历史版本恢复是"在输入框里填编号"，可用性差

- 分享 id 只有 32 bit，读取不限流，知道 id 就能写（无 ETag 冲突检测）

## 五、方法论备忘

这次修复值得记下来的两条：

1. **长评估报告要先验证再动手。** 报告里 P0/P1/P2 各七项，逐条核对后发现全部属实，但仍有细节偏差——比如报告说 DOMPurify 默认允许 `<style>`，实测是不允许的（两种档位 `hasStyle` 都是 false）。照抄会做无用功。

2. **同一类 bug 要找共同根因，不要逐个打补丁。** 21 项里有 12 项追到两个根因：「切换文档时状态没收敛」和「改写文本走了太多条路」。修根因（`resetDocContext`、`replaceRange`）比修 21 个症状持久。
